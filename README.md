# «Эпицентр» — симулятор зомби-катастрофы

Демо-версия игры по питчу `docs/Epicenter_Pitch.pptx`. Кампания из четырёх этапов в разном масштабе управления — от одного человека до целой страны:

1. **Учёный** — побег из подземной лаборатории (вид сверху, фонарь, заражённые, несколько этажей).
2. **Оператор** — диспетчерская: звонки, службы, очаги заражения на карте района.
3. **Эвакуация** — город с группами выживших: вы выбираете технику (автобус, грузовик, джип, вертолёт, БТР) и группу; машина едет по улицам, грузит людей и везёт на аэродром, пока заражённые толпы идут к людям и технике (по духу Atom Zombie Smasher).
4. **Штаб** — страна: бригады, губернаторы, исследования, фронт, политические события.

Плюс особый этап «Возвращение» (рейд за лекарством) и пять концовок. Результаты каждого этапа влияют на следующие.

Игра написана на чистом JavaScript + Canvas 2D, без фреймворков, без шага сборки и без внешних зависимостей. Android-приложение собирается Python-скриптом **без Android SDK**: манифест, DEX-оболочка с WebView, ZIP и подпись v1+v2 формируются вручную.

Текущая версия: **0.8.0-demo** (versionCode 11).

---

## Быстрый старт

**Поиграть на компьютере:** откройте `dist/Epicenter-web.html` в Chrome, Edge или Firefox. Это один самодостаточный файл, интернет не нужен.

**Поиграть на телефоне:** установите `dist/Epicenter-demo.apk` (нужно разрешить установку из неизвестных источников).

**Разработка:** откройте `game/index.html` в браузере — это та же игра из отдельных файлов, правки видны после перезагрузки страницы. Если браузер ограничивает `file://`, запустите локальный сервер:

```bash
python3 -m http.server -d game 8000
# затем http://localhost:8000
```

Режим разработчика (все этапы открыты в «Выбор этапа»): пять раз нажмите на номер версии в правом нижнем углу главного меню.

## Структура

```
game/                 исходники игры (то, что попадает в APK как assets)
  index.html          разметка, базовые стили, порядок подключения скриптов
  css/ui.css          интерфейс: HUD, панели, кнопки, обучение, адаптация под экраны
  js/                 код игры (порядок загрузки важен, см. ниже)
  img/art_*.png       иллюстрации для слайдов и карточек (генерируются tools/make_art.py)
tools/
  build_apk.py        сборка APK без Android SDK → dist/*.apk
  build_web.py        сборка HTML-версии одним файлом → dist/Epicenter-web.html
  verify_dex.py       независимая проверка classes.dex (структура + дизассемблер)
  verify_apk.py       проверка resources.arsc, адаптивной иконки, ссылок манифеста
  make_art.py         генератор иллюстраций game/img (детерминированный)
  make_icon.py        генератор иконки приложения → icon/
icon/                 иконка приложения (обычная и адаптивная: фон + передний план)
signing/              ключ подписи APK (демо-ключ, см. раздел «Подпись»)
tests/                автотесты и бот баланса на Playwright
dist/                 готовые сборки
docs/                 питч проекта
CHANGELOG.md          история версий
```

| `maps.js` | Генераторы псевдо-3D карт: район (этап 2), город с рекой и аэродромом (этап 3), страна (этап 4) |
| `stage2.js` | «Оператор»: типы вызовов `TYP`, очаги, части служб `STN`, дорожный граф `ROAD` и маршруты (Дейкстра), модели машин `VEH`, кат-сцена первого «ожившего», обучение |
| `stage3.js` | «Эвакуация»: дорожный граф города, группы выживших с таймерами, парк техники и приказы (выбор машины → тап по группе → предпросмотр маршрута и риска), толпы заражённых по улицам, БТР-приманка, погрузка/выгрузка, пауза планирования, время суток |

| `stage4.js` | «Штаб»: регионы, бригады, губернаторы, исследования, фронт, предложение возглавить страну, фракции, обучение |

### Как устроен этап

Каждый этап — объект с методами `enter()`, `exit()`, `update(dt)`, `draw()`, `tap(x, y)` (координаты логического холста) и полем `tut` (ключ справки в `TUT`). Этапы 2–4 также реализуют `coachUpdate(dt)` (что «живёт» во время обучения, пока игровое время стоит) и `coach()` (шаги обучения). Переключение — `setMode(Этап)`; цепочку этапов ведёт `flow.js`.

На картах этапов 2–4 мир имеет ширину 330 логических пикселей; справа — панель. `MW` — ширина области карты, `OX = MW − 330` — сдвиг мира (на широких экранах слева дорисовывается продолжение города).

## Сборка

Нужен Python 3.9+.

```bash
pip install cryptography          # для подписи APK
pip install pillow numpy          # только для генераторов картинок и иконки

python3 tools/build_apk.py        # dist/Epicenter-demo.apk (+ noicon и safe)
python3 tools/build_web.py        # dist/Epicenter-web.html

python3 tools/verify_dex.py       # проверка classes.dex
python3 tools/verify_apk.py       # проверка ресурсов
jarsigner -verify dist/Epicenter-demo.apk   # проверка подписи v1 (если установлен JDK)
```

Новая версия: поменяйте `versionCode`/`versionName` в `build_axml()` (`tools/build_apk.py`) и строку версии в `game/js/title.js`.

### Что внутри APK

- Пакет `com.epicenter.game`, minSdk 21, targetSdk 33, только горизонтальная ориентация.
- Activity с WebView загружает `file:///android_asset/index.html`.
- Нативная часть (DEX генерируется в `build_dex()` прямо из байткода, исходников на Java нет): JavaScript и доступ к файлам, `setDomStorageEnabled(true)` (без него в WebView не работает localStorage и не сохраняется прогресс), `setTextZoom(100)` (системный размер шрифта не ломает вёрстку), экран не гаснет, полноэкранный режим с автоскрытием панелей, рисование в области выреза камеры (`layoutInDisplayCutoutMode = SHORT_EDGES`, только на Android 9+).
- После изменения `build_dex()` обязательно прогоните `tools/verify_dex.py`.

Три варианта в `dist/`:

| Файл | Для чего |
|---|---|
| `Epicenter-demo.apk` | основной |
| `Epicenter-demo-noicon.apk` | без ресурсов иконки — если на каком-то устройстве не ставится основной |
| `Epicenter-demo-safe.apk` | прежняя нативная часть (без textZoom и выреза, но с включённым сохранением), проверенная на реальном телефоне |

Если команде удобнее Android Studio или Capacitor — папку `game/` можно целиком положить в `assets` обычного WebView-проекта.

### Сохранения

Прогресс (концовки, достижения, пройденное обучение) и настройки хранятся в двух местах: `localStorage` и резервная копия в IndexedDB (объект `Store` в `core.js`). При запуске копии объединяются — прогресс только накапливается, поэтому очистка одной из копий ничего не теряет. Если сохранять некуда (например, приватный режим браузера), игра предупреждает игрока, а в «Настройках» видно состояние сохранения. Ключи: `epi.prog` (прогресс), `epi.opt` (настройки).

### Подпись

Ключ лежит в `signing/` и создаётся автоматически при первой сборке, если его нет. Пока все собирают одним ключом, новые версии ставятся поверх старых без потери прогресса. Если ключ потерять или сменить, приложение придётся удалить и поставить заново. Это демо-ключ: для публикации в магазине нужен отдельный, и его не стоит хранить в общем репозитории.

## Тесты

Автотесты гоняют игру в headless Chromium через Playwright и пишут скриншоты в `tests/out/`.

```bash
cd tests
npm i
npx playwright install chromium
npm run all
```

| Скрипт | Что проверяет |
|---|---|
| `campaign.js` | сквозной прогон: этап 1 (бот), этап 2, рейд, концовка |
| `tutorial.js` | интерактивное обучение этапов 2–4 кликами по подсветке |
| `stage1.js` | диалоги учёного, «память» о встреченных заражённых |
| `panel.js` | панель вызова не мигает, метки вызовов не накладываются |
| `ui.js` | пауза, пропуск кат-сцены, пропуск слайдов |
| `phone-lock.js` | без телефона лестница наверх закрыта |
| `save.js` | прогресс переживает перезапуск: обычный браузер, очищенный localStorage, WebView без localStorage, полное отсутствие хранилища |
| `screens.js` | скриншоты всех этапов на заданном экране |
| `web.js` | HTML-версия: клавиатура, пауза, обучение мышью (сначала `tools/build_web.py`) |
| `balance.js` | бот баланса: `node balance.js <2\|3> <реакция, с> <точность> <прогонов>` |

### Баланс (по боту)

- **Этап 2**, 180 с: около 40–45 вызовов, примерно половина ясна сразу, есть ложные. Удержание района — не больше 4 очагов и 14 потерь в конце. Бот с реакцией 1,0 с проходит всегда, 1,6 с — в большинстве смен, 2,4 с — редко.
- **Этап 3** (210 с, 21 группа, 1325 человек): бот «польза/время без смертельных маршрутов» эвакуирует около 55–65%, с БТР-приманкой — немного больше, медленный бот (реакция 4 с) — около 50%. Цель удержания — не менее 55%. Ключевые числа — `VT`, `GRP` и константы в `update()` `stage3.js`: время смерти группы (`doom`), скорость и размер толп, урон по технике.

Ключевые числа — в начале `stage2.js` (`TYP`, частоты в `update`) и в `update()` `stage3.js`.

## Соглашения

- Без `?.` и `??` — старые системные WebView их не понимают.
- Тексты интерфейса и комментарии — на русском.
- Панель и HUD обновляются функциями `panel(html)` и `hud(html)`: DOM не пересоздаётся, меняются только отличия. Если элемент должен создаваться заново (например, карточка другого вызова), дайте ему `data-key`.
- Числа, которые должны плавно «докручиваться», выводите через `Cnt.h(ключ, значение, формат)`.
- Подсказки, зависящие от устройства, — через `HINT('для сенсора', 'для клавиатуры')`.

## Что не проверено

- Сборки 0.5–0.6.1 не запускались автором на реальном телефоне; звук и вибрация проверены только в браузере.
- Нативные изменения (вырез экрана, textZoom) проверены валидатором DEX, но не на устройстве.
